# 能力边界与未知未知

## 起因：PET 视频理解问题

PET 实验暴露出一种隐蔽失效：模型能读取视频帧，便认为自己能够理解视频动作；能生成静态图片，便认为自己可以通过逐帧生成得到连续动画。

但接口可用、输入可读、输出可生成，都不能证明系统具备完成整个任务所需的能力。

对于动画验收，至少要区分：
- 静态画面理解；
- 人物姿态识别；
- 连续动作理解；
- 短时间帧间变化识别；
- 动作自然度与流畅性评价。

读取稀疏帧可能遗漏短暂运动变化。能够描述视频内容，也不等于能够可靠评价动作质量。实际能力还取决于输入管线、帧采样、时间信息、分辨率和模型本身。

同样，静态图像生成能力不能自动推出跨帧一致性、运动控制和连续动画生成能力。

## 三种不同问题

### 1. 识别已知能力缺口

已经知道任务需要某项能力，只是不确定当前模型或工具是否具备。

例如：已知动画验收需要时序运动评价，但当前视频输入和模型是否足够可靠尚未验证。

可通过文档核对、能力探针、真实样本测试和独立评价处理。

### 2. 推导隐含能力需求

用户没有明确说出某项能力，但它是完成目标所必需的。

例如用户要求“自然连续的 2D 动画”，Agent 需要推导出动作时序、帧间变化、角色一致性和最终播放验收等要求。

可借助领域知识、任务分解、技术资料和验收条件分析辅助发现。

### 3. 发现未知未知

Agent 连自己缺少什么能力、任务还依赖什么能力都没有意识到。

PET 中，模型没有主动提出“我是否真的能观察和评价帧间动作流畅度”这个问题，就是这种情况。

它比检查已知能力缺口困难得多。不能假设列一份能力清单或加一句“注意自身局限”就能解决。

## 能力声明需要证据

至少区分：

| 状态 | 含义 |
|---|---|
| 已验证 | 在与当前任务相关的条件下有实际测试证据 |
| 有条件支持 | 只在特定输入、范围或难度下验证 |
| 未验证 | 尚无足够证据 |
| 已发现缺陷 | 实际测试暴露出能力问题 |

还要区分：
- 接口存在；
- 文档声明支持；
- 模型理论上可能具备；
- 在代表性任务上实际验证；
- 足以支撑当前任务的验收要求。

能力探针必须覆盖任务真正依赖的能力层级。通过简单动作分类测试，不足以证明模型能评价复杂动画的自然度。

## 对 Agent 系统的暂定处理

现阶段可采用：
- 一条通用原则：检查当前方案依赖的模型、工具和信息通道是否真正具备所需能力；
- 按需调用的领域知识文档：沉淀已知的模型和工具能力边界；
- 实际测试：对关键但未验证的能力设计代表性探针；
- 战略监督：当 Worker 的方案依赖未经验证的能力时，要求补充调查或验证。

不要求每个任务都生成庞大的能力清单。只检查可能改变方案选择或验收结论的关键能力依赖。

## 当前不打算解决的范围

“让模型发现所有自己尚未想到的能力需求”属于未知未知发现问题。现有 PET 案例能说明问题存在，但样本不足以支撑通用机制设计。

当前先处理已知能力缺口和可由领域资料推导的能力需求。未知未知作为开放研究问题保留，不把它写成当前系统必须保证的能力。
