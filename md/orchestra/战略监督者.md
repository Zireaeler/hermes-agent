# 战略监督者：Orchestra 要解决的核心问题

## 核心定位

> Orchestra 是复杂问题解决过程中的战略监督者。

Orchestra 的价值可能不在于让 Worker 更少犯错，而在于让整个系统不再被某一次错误判断长期绑架。

Worker 可以在局部任务中自主调查、设计、实现、测试和修复。问题在于：Worker 一旦选错问题表征或技术路线，后续的局部工作可能越来越熟练、产物越来越多，却始终无法实现人类真正想要的结果。

Orchestra 要处理的是跨任务、跨阶段的整体判断：当前解决的问题是否正确，当前策略是否仍然有效，已有结果是否支持继续投入，以及何时需要重新审视整个问题。

## 与普通任务管理的区别

普通任务管理主要关注：
- 任务是否完成；
- 当前执行是否成功；
- 下一项工作是什么；
- Worker 是否遇到错误。

战略监督还需要关注：
- Worker 正在解决的局部问题是否仍对应原始目标；
- 当前策略依赖的关键假设是否成立；
- 局部成功是否掩盖整体目标没有改善；
- 是否存在更根本的问题理解错误；
- 当前路径是否已经失去继续投入的理由；
- 是否需要改变问题表征，而不只是修改实现。

## 两个时间尺度

**Worker 的执行循环**：理解任务、查明局部事实、形成方案、执行、根据反馈修正，直到完成当前责任或发现需要交回控制的关键问题。

**Orchestra 的战略循环**：恢复原始意图和项目现实，吸收 Worker 结果，观察主要缺口与承重假设，判断当前策略是否仍值得维持，必要时推动全局重审并重新组织任务。

战略监督不意味着 Orchestra 要成为所有领域的专家，也不意味着它必须亲自审核每个技术方案。它可以通过委派新的 Worker 获取独立研究、诊断或验证结果。

## 一个关键区别：局部修复与全局重审

假设 PET Worker 连续修复动画问题：

1. 增加参考图；
2. 调整提示词；
3. 修改抽帧和补帧；
4. 增加后处理。

这些操作可能分别有局部价值。但如果核心动作连续性始终不达标，Orchestra 应当重新提出问题：

> 我们是否仍然应该研究“如何改进逐帧生图”，还是应该回到“如何实现符合要求的连续 2D 动画”？

全局重审允许质疑：
- 原始问题表述；
- 对任务属性的理解；
- 技术路线；
- 能力前提；
- 实验与验收方式；
- 已投入工作所形成的路径依赖。

## 讨论边界

战略监督不是：
- 固定的 Planner → Coder → Reviewer 流水线；
- 对每次 Worker 失败都进行干预；
- 要求 Orchestra 深入复做所有专业研究；
- 仅根据失败次数触发的自动重试或换线；
- 让另一个 LLM 对原 Worker 的结论简单打分。

它需要判断什么时候正常困难值得继续，什么时候出现了策略失效迹象，以及什么时候应该让系统暂时脱离原来的问题表征。
