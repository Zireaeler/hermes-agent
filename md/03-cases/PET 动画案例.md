# PET 动画案例：局部执行成功与整体能力缺口

## 原始目标
制作一个非像素风格、能够在桌面运行的 2D PET。角色参考图由用户提供，要求角色视觉表现和动画达到正常 2D 动画的帧率、动作连续性与流畅度。任务同时要求参考 OpenAI PET 制作文档。

## 观察到的过程
- Agent 最初沿着 PET 文档相关实现方式推进。
- 执行约四小时后，Agent 最终尝试了视频生成模型。
- 但在视频验收环节，文本模型仍认为自己可以通过读取视频帧理解动作。
- 用户指出：模型没有可靠观察帧间人物变化、短时间动作变化和整体运动流畅度的能力。

## 关键问题
1. **技术路线锚定**：参考文档可能影响了初始解决路线的选择。
2. **能力边界误判**：模型把“能读取视频帧”推断为“能可靠评价视频动作”。

第二个问题更深：模型可能没有意识到时序运动评价本身是一个独立的验收能力需求。

## PET 对 Orchestra 的启示
- 观察 Worker 是否持续产生局部产物，不足以判断整体目标是否正在实现。
- 应区分图像读取、姿态识别、时序理解和动作质量评价。
- 需要检查验收方式是否真的能够观察用户要求的属性。
- 当验收能力未经验证时，不能让 Worker 自己的文字判断成为完成依据。
- 发现关键能力缺口后，可能需要更换工具、评价方式或技术路线。

## 目前不能据此断言
- 所有文本模型都完全无法理解视频动作；
- 所有逐帧生图路线都无法制作连续动画；
- 视频生成一定优于骨骼动画；
- 一个 PET 案例足以证明通用 Agent 的能力边界识别机制。

这些结论需要具体模型、输入管线、任务条件和对照实验支持。
